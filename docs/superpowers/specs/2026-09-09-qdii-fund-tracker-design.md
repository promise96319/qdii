# QDII 纳指100 / 标普500 场外基金每日限额与费率查询页 — 设计文档

日期：2026-09-09
状态：已批准，待实现

## 1. 背景与目标

定投纳斯达克100 和标普500 的 QDII 场外基金时，基金公司因外汇额度紧张频繁限购或暂停申购，
且限额逐日变动。投资者无法预先知道当天实际能投多少钱，只能逐只手动查看。

本项目产出一个每日自动更新的静态网页，一屏回答：**今天哪些基金能买、各能买多少、总费率多低。**

### 成功标准

- 打开页面即可看到当天全部可申购的纳指100/标普500 场外基金，按额度与费率排序
- 每只基金展示：单日限额、申购状态、买入费率、年化持有费率、卖出费率、免赎回费天数
- 数据每日自动更新，无需人工干预
- PC 与移动端均可正常使用

### 非目标（明确不做）

- 不做实时行情、净值走势、持仓分析
- 不做交易功能，不接入任何账户
- 不做微信理财通口径（无公开数据源，见 §9）
- 不做「今日 vs 昨日变化」视图（本期不做，但历史数据存档以备后续实现）

## 2. 关键领域知识（调研结论）

以下事实经基金公司公告原文核实，是数据源选型的依据。

### 2.1 限额由基金公司设定，非销售平台

支付宝（蚂蚁基金销售）、微信理财通（腾安基金销售）、天天基金（上海天天基金销售，
东方财富旗下）三者法律地位相同，均为证监会批准的**独立基金销售机构**，均属代销。
限额由基金公司公告统一设定，代销渠道适用同一条。

### 2.2 限额的计算单位

**单日 x 单个基金账户 x 单只基金代码**，跨销售渠道合并计算。

| 维度 | 规则 | 依据 |
|---|---|---|
| 不同基金公司 | 各自独立 | 限额由各公司分别公告 |
| 同一基金的 A 类 / C 类（不同代码） | 各自独立 | 广发公告：「不同份额的申请将单独计算限额」 |
| 同一代码跨支付宝/微信/天天基金 | 合并计算 | 大成公告：「通过各代销机构…单日单个基金账户…累计金额应不超过10元」 |

### 2.3 直销与代销分开计额

大成纳指100（000834）2026-06-03 公告同时列出两条：直销渠道限 100 元、各代销机构限 10 元。
本项目只覆盖代销口径。

### 2.4 超限的执行方式

下单时不报错，T 日盘后清算时确认失败，超出部分原路退回（约 T+4 到账）。
多渠道等额申购时为随机确认其中一笔。

## 3. 数据源

三个接口，均无需鉴权，均已实测通过。

### 3.1 基金池全量

```
GET https://fund.eastmoney.com/js/fundcode_search.js
```
返回全市场 27811 只基金，格式 `[代码, 拼音, 名称, 类型, 全拼]`。

### 3.2 限额与费率（主数据源）

```
GET https://fundmobapi.eastmoney.com/FundMApi/FundRateInfo.ashx
    ?FCODE={code}&deviceid=1&plat=Android&product=EFund&version=6.5.5
```

字段映射：

| 响应字段 | 含义 | 用途 |
|---|---|---|
| `SGZT` | 申购状态：开放申购/限大额/暂停申购 | 状态列 |
| `MAXSG` | 单日累计申购限额（元） | 限额列、主排序键 |
| `MINSG` / `MINDT` | 申购起点 / 定投起点 | 详情 |
| `MGREXP` | 管理费率（%/年） | 年费求和 |
| `TRUSTEXP` | 托管费率（%/年） | 年费求和 |
| `SALESEXP` | 销售服务费率（%/年） | 年费求和 |
| `sg[]` | 申购费阶梯，`source`=原价，`rate`=折后价 | 买入费率 |
| `sh[]` | 赎回费阶梯，`time`=持有期限，`rate`=费率 | 卖出费率、免费天数 |
| `SSBCFMDATA` / `RDMCFMDATA` | 申购/赎回确认日 T+N | 详情 |

补充信息（基金名称、公司、类型）取自：
```
GET https://fundmobapi.eastmoney.com/FundMApi/FundBaseTypeInformation.ashx?FCODE={code}&...
```

### 3.3 支付宝在售标记

```
GET https://www.fund123.cn/matiaria?fundCode={code}
```
服务端渲染，正文含 `window.context = {...}`，取
`materialInfo.fundBrief.saleStatus`，三种取值：`正常申购` / `暂停销售` / `不可售`。

**注意**：同页的 `titleInfo.fundLimit` 恒为 `0--`（坏字段），
`fundBrief.purchaseRatio` 恒为 `--`。支付宝侧的限额数字与申购费折扣**无法通过公开接口获取**。

## 4. 基金池构建规则

1. 从全量列表按名称关键词匹配：`纳斯达克100`、`纳指100`、`标普500` → 92 只
2. 排除纯场内 ETF：代码前缀 `15` / `51` / `52` / `56` / `58` → 剔除 7 只，余 85 只
   **注意：16 开头的 LOF 必须保留**（161130 易方达纳指100、161125 易方达标普500、
   160213 国泰纳指100 均为场外可申购，早期规则误将其剔除）
3. 排除美元份额：名称含 `美元`/`美汇`/`美钞`/`现汇`/`现钞` → 剔除 28 只，得 57 只人民币场外基金
4. 支付宝在售状态标记（不过滤，仅标记）

2026-09-09 实测分布：可买 33 只、暂停 19 只、支付宝不卖 5 只。

份额类型无法由代码前缀推断（022664 华泰柏瑞 I 类支付宝可买，021000 南方 I 类不可买），
必须逐只查询接口。

## 5. 数据模型

```json
{
  "code": "018043",
  "name": "天弘纳斯达克100指数发起(QDII)A",
  "company": "天弘基金",
  "index": "NDX100",
  "share_class": "A",
  "status": "限大额",
  "max_buy": 100,
  "min_buy": 10,
  "fee_mgmt": 0.50,
  "fee_trustee": 0.10,
  "fee_sales": 0.00,
  "fee_annual": 0.60,
  "fee_buy": 0.10,
  "fee_buy_original": 1.00,
  "redeem_free_days": 365,
  "redeem_tiers": [
    {"min_days": 0,   "max_days": 7,    "rate": 1.50},
    {"min_days": 7,   "max_days": 365,  "rate": 0.50},
    {"min_days": 365, "max_days": null, "rate": 0.00}
  ],
  "confirm_days": 2,
  "alipay": "正常申购",
  "stale": false
}
```

`redeem_tiers` 区间语义：左闭右开，`min_days <= 持有天数 < max_days`；
`max_days: null` 表示无上界（最后一档）。`redeem_free_days` 即首个 `rate == 0`
档位的 `min_days`。

输出文件：
- `data/latest.json` — 最新快照，含 `updated_at` 与基金数组
- `data/history/YYYY-MM-DD.json` — 每日归档，为后续「变化对比」留数据

## 6. 数据处理规则

### 6.1 免赎回费天数归一化

`sh[]` 中 `rate` 为 0 的档位对应的 `time` 字段格式不统一，实测出现过：
`持有期限 ≥ 7天`、`≥ 30天`、`≥ 365天`、`≥ 730天`、`≥ 1095天`、`≥ 2年`。

统一解析为整数天数，`N年 → N × 365`。无 0 费率档位时置 `null`，展示为「无免费档」。

### 6.2 空值处理

- 销售服务费为空字符串（如 160213）→ 求和时按 0 计，但详情标注「未披露」
- `MAXSG` 为空（如 022525）→ `max_buy = null`，展示为 `—`，**不可显示为 0**（会被误读为不能买）

### 6.3 状态与限额矛盾

暂停申购的基金 `MAXSG` 可能仍保留历史残值（如 050025 状态为暂停申购但 MAXSG=100）。
**以 `SGZT` 状态为准**，状态为暂停时不展示限额数字。

## 7. 容错策略

- **单只基金抓取失败** → 沿用上一次 `latest.json` 中该基金的值，置 `stale: true`，
  页面灰显并提示「数据可能过期」
- **整体成功率 < 80%** → 中止写入，保留旧的 `latest.json`，Actions 以非零码退出报错
- 页面顶部始终显示数据抓取时间；若非当日，显著提示「数据来自 X 月 X 日」

宁可展示带明确标记的旧数据，也不能覆盖成空白。

## 8. 页面设计

### 8.1 排序

默认：**可买优先 → 限额从高到低 → 同限额按年化费率从低到高**。
表头可点击切换排序键。暂停申购的基金默认折叠于表格底部，可展开查看。

### 8.2 PC 端

完整表格，列：代码、名称、限额、状态、年费、买入费率、**卖出费率**、免赎回费天数、支付宝标记。

「卖出费率」列展示最短持有档的费率（即最坏情况，多数为 1.50%），
与「免赎回费天数」列配合即可回答「现在卖要付多少」和「持有多久卖免费」两个问题。
完整赎回费阶梯在行展开时呈现。表头可点击排序。

### 8.3 移动端

同一数据渲染为卡片流。卡片首屏仅展示**限额、年费、状态**三项核心信息，
点击展开申购费阶梯、赎回费阶梯、免费天数、确认日。
**不使用横向滚动表格。**

### 8.4 共用元素

- 顶部概览：`今日可买 N 只 / 暂停 M 只`
- 纳指100 与标普500 分组展示
- 支付宝在售状态以角标呈现
- 页脚标注数据来源与免责说明：限额以实际下单页为准

## 8.5 视觉规范

设计定位：**每天扫一眼的数据工具，不是阅读型页面。** 所有取舍倒向扫描效率。

### 主题

亮/暗两套配色，**默认跟随系统** (`prefers-color-scheme`)，并提供手动切换（选择存 localStorage）。
全部颜色以 CSS 变量定义在 `:root`，暗色在 `@media (prefers-color-scheme: dark)`
与 `[data-theme="dark"]` 下各覆写一次，保证手动切换双向生效。

### 配色

中性底色，无渐变、无阴影、无装饰性圆角。颜色只用于承载语义，不用于修饰。

| 语义 | 亮色 | 暗色 |
|---|---|---|
| 页面底 | `#fafaf9` | `#0f1115` |
| 卡片/行底 | `#ffffff` | `#171a1f` |
| 主文字 | `#1c1e21` | `#e8e6e3` |
| 次要文字 | `#6b7280` | `#9096a1` |
| 分隔线 | `#e5e7eb` | `#2a2f37` |
| 可正常买 | `#0f7b3f` | `#3fbd6d` |
| 限额偏小 | `#a16207` | `#d9a441` |
| 已暂停 | `#9ca3af` | `#6b7280` |

状态色仅用于小色点与状态文字，不做整行大面积着色（33 行全彩会失去焦点）。

### 字体与数字

- 正文：系统字体栈
- **所有数字（限额、费率、天数）使用等宽字体** `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`，
  并 `font-variant-numeric: tabular-nums`。比例字体下 `0.60%` 与 `1.20%` 无法纵向对齐，
  丧失扫描比较能力，这是本页面的核心交互
- 限额为全页视觉权重最高的元素：字号最大、字重最重

### 密度

- PC 表格行高紧凑（约 36px），目标首屏可见 15 行以上
- 移动端卡片一屏可见 5–6 张，卡片内不做多余留白
- 断点 `768px`：以上为表格，以下为卡片流

### 移动端卡片

首屏仅三项：**限额、年费、状态**。点击展开申购费阶梯、赎回费阶梯、免赎回费天数、确认日、支付宝标记。
卡片不做横向滚动。

### 可访问性

- 状态不单独依赖颜色，同时有文字标签（色盲可用）
- 正文对比度满足 WCAG AA
- 表头排序按钮可键盘操作

## 9. 已知限制

1. **支付宝申购费折扣无法获取** — 页面展示申购费原价与天天基金折后价。
   天天基金折后价是在天天基金买入的实际费率；支付宝折扣通常同为 1 折但无法自动验证。
2. **微信理财通无公开查询接口** — 不覆盖，页面不作任何微信口径声明。
3. **代销机构可在基金公司额度之上自行收紧**（不可放宽）— 实践中少见，
   若发生则页面显示的限额高于支付宝实际值。故页脚提示以下单页为准。
4. 数据为每日快照，非实时。

## 10. 技术架构

```
GitHub Actions (每日 09:30 北京时间 / 01:30 UTC，另支持手动触发)
  └─ Python 3 脚本（仅标准库 urllib + json，零第三方依赖）
       ├─ 拉取基金池 → 过滤 → 候选代码列表
       ├─ 逐只抓 FundRateInfo + FundBaseTypeInformation
       ├─ 逐只抓 fund123.cn 取支付宝状态
       └─ 合并 → data/latest.json + data/history/YYYY-MM-DD.json
            └─ 提交回仓库 → GitHub Pages 部署
                 └─ index.html（单文件，原生 JS，无框架无构建）fetch 渲染
```

请求量：1 + 57×2 ≈ 115 次，请求间隔 0.2s，整轮约 25 秒。

## 11. 测试策略

抓取脚本的纯函数部分走 TDD，用真实响应存为 fixture，不测网络层。

必测：
- 免赎回费天数归一化（覆盖 `7天`/`30天`/`365天`/`730天`/`1095天`/`2年`/无免费档）
- 年费求和（含空值字段）
- 状态与限额矛盾的处理（暂停时不输出限额）
- 排序比较器（限额优先、同额比费率、null 限额排序位置）
- 基金池过滤规则（**必须覆盖 16 开头 LOF 不被误杀**这一回归用例）
- `window.context` 解析（含解析失败的降级路径）
